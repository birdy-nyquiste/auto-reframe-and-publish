# 在任务头中直接使用 Blog 字段

本决策只修订 ADR-0004 中“不透明目标标识”的任务头约束，以及旧设计中的本地目标映射；批次标记、相邻消息和单篇来源等输入窗口决策保持不变。

微信任务头以 `#投稿` 开始，直接携带当前 Blog 接口允许由投稿者指定的发布字段。`author.name` 必填；嵌套字段使用点路径，例如 `author.slug`。项目不再维护“目标 ID 到 Blog 字段”的本地映射。

`洗稿指令` 是本地内容处理字段，可以省略；省略时使用默认洗稿提示词。抓取证据、结构化来源、洗稿输入与产物、状态和审计记录仍按现有本地任务模型保存。

任务头只能接收适配器声明为安全且可由投稿者指定的 Blog 字段。正文、标题、封面、图片、slug、发布状态和来源 URL 等由流程生成或由运行级授权控制的字段不能从微信任务头注入。是否发布仍只由操作人在运行命令中明确决定。

任务记录保存已经解析和类型化的 Blog 发布字段，发布时直接交给 Blog 适配器；配置文件只保存接口地址和密钥环境变量名，不保存作者或目标映射。

现有任务 Schema v2 的 `target_id` 仅作为旧改写产物完整性校验所需的兼容投影，值由 `publication_fields.author.name` 确定；它不是 Blog 查询 ID，也不得参与字段映射。待任务 Schema 版本化迁移时再移除该兼容字段，避免破坏历史任务和改写提交的校验。
